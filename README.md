# Specimen / Lab Requisition Scanner — proof of concept

**Proof of concept. Not for clinical use. Always verify against the paper requisition.**

A small web app (PWA) for community nursing that reads the ticked tests on a photographed BC lab requisition (LifeLabs D2350 or a printed EMR test list) and shows them as a checklist for the nurse to confirm.

Live demo: https://kimberleywilliams00-ai.github.io/specimen-scanner-poc/

## Privacy design
- **Everything runs on the device.** Image processing (OpenCV.js) and text recognition (Tesseract.js) are bundled in this repo and run in the browser.
- **Nothing is stored or sent.** Photos stay in memory only and are cleared on *Finish* / *Discard*. No uploads, analytics, cookies, localStorage or IndexedDB. A strict Content-Security-Policy only allows the app's own files.
- The service worker caches only the app's own static files (for offline use); it never sees or stores photos.
- This repository contains no patient data or requisition photos.

## Updates (v3.1+)
The service worker is network-first for the app itself (page, app JS/CSS, `version.json`), so a new deploy loads on the next open while online; the cache is only an offline fallback. Large engine files under `vendor/` are cache-first (cache `req-scanner-vendor-N`; bump N if they change). The page checks for updates on open and when brought back to the foreground, reloads once when a new version takes over (only when idle), and shows *Update available - tap to reload* if `version.json` differs from the running version. The version is shown on the start screen and in the footer.

To release a new version, bump it in `version.json`, `js/app.js` (`APP_VERSION`), `sw.js` (`VERSION`, `Q`) and the `?v=` query strings in `index.html`.

## Collection Summary (v3.2+)
After **Confirm tests** the app shows a *Collection summary*: what to collect grouped by tube/container (sharing rules: see v3.3 below; centrifuged LifeLabs SST vs unspun SST for BCCDC are always separate), time-critical/fill requirements, do-not-centrifuge warnings, patient preparation (incl. instructions read from the requisition), processing, storage/transport, extra requisition forms and destination, labelling, and the source of every line. Tests without any data get an amber *No collection info yet* card - nothing is guessed. A general CLSI order-of-draw note is labelled as general guidance.

Data: `js/collection_data.js`, transcribed verbatim from LifeLabs Lab Test Information (Lower Mainland) entries exported and verified by the nurse (each entry carries its *Last Published Date* and *last checked* date). It is generated by a build script that checks every value against the source text; the source PDFs are not part of this repository. Directory: https://tests.lifelabs.com/. **Prototype - verify against current LifeLabs/BCCDC guidance before collecting.** The summary lives in memory only; *Done / clear* wipes it.

## Tube rules, local practice and requisition forms (v3.3+)
The Collection summary assigns tubes in this order: **(a)** the LifeLabs *Quick Reference Collection Chart, Lower Mainland and BC Region* (Doc#49141, effective 2024-04-08; Lower Mainland columns) encoded in `js/tube_rules.js` - tube type, size and colour, *Mix N times*, and which tests share **one** tube vs need **their own** tube; tests from different chart groups never share and chart tube sizes override per-test container sizes (differences are flagged); **(b)** sharing rules stated in the per-test LifeLabs Lab Test Information entries (`js/collection_data.js`), plus the combined-tube instruction printed on the BCCDC PHL *Serology Screening Requisition* (PHRQ_HVS_0001F, Version 1.0 August 2026; `js/requisition_forms.js`); **(c)** otherwise a separate tube marked *confirm with lab* (no volume-based sharing). BCCDC unspun serology is never put in a centrifuged LifeLabs tube. Tests that are only on the chart (or only on the PHL form) get a tube card but are marked *processing/storage not yet available*. Where the chart is visually ambiguous, the app shows our reading as *Confirm with lab*.

Local practice rules (`js/local_rules.js`) are kept separate from LifeLabs data and carry their own source and date (VCH community practice, K. Williams, 2026-10-10): **collect a full tube** for every blood tube (per-test volumes are shown only as *lab minimum*), and for **PTT** the summary asks *Client on heparin or unknown anticoagulant?* - *Yes*/*Unsure* shows a red card (cannot be collected in community; redirect to a LifeLabs Patient Service Centre) and PTT is left out of the tubes; the citrate-tube instructions for PTT appear only after *No*. The answer is held in memory only.

Source documents (chart, form, per-test PDFs) are not part of this repository; the data files are checked against their text by build scripts.

## Local practice tube rules (v3.4)
Three further local practice rules (`js/local_rules.js`, source *VCH community practice (K. Williams), 2026-10-11*) take priority over the LifeLabs chart and per-test entries where they conflict:
1. **HCV RNA** (Hep C viral load / PCR; HCV genotyping shares that tube per the BCCDC form) and **HIV Viral Load** each get their **own 6.0 mL EDTA** lavender tube (the chart's *confirm with lab* flag for this is removed).
2. **BCCDC serology tube:** any combination of syphilis, HIV, hepatitis A/B/C serology (incl. Hep A IgM, Hep B core/surface Ab/Ag, HBeAg, Hep B screen/carrier, acute/chronic hepatitis profiles) and other serology goes in **one SST** for BCCDC, following the BCCDC PHL Serology Screening Requisition (PHRQ_HVS_0001F); prenatal panel = 2 SSTs. This replaces the chart's separate Hep A IgM/Hep B tube and two tubes per profile. Per-test LifeLabs centrifuge instructions are kept; when they differ within the tube, one amber note says *LifeLabs pages differ on centrifuging for some of these tests - confirm with BCCDC/LifeLabs* (the tube is not split).
3. Communicable disease tests (HIV, hepatitis, syphilis) go to BCCDC and **never share a tube** with non-communicable tests (lipids, chemistry, etc.) - enforced in the tube planner.

## Using it on an iPhone
1. Open the link above in Safari (first load downloads ~25 MB of engine files, then works offline).
2. Optional: Share → *Add to Home Screen*.
3. Tap **Take photo**, photograph the test list, review the results, and check every item against the paper form before confirming.
